# FP27b2: the armed port takes the catalogue's slug set

> Written by: Claude (opus-compat-w5), 2026-11-23

The API learns a shard's slug only from the file it validates, so it
cannot name one shard's armed state up front. The `armed` port now also
takes a `ReadonlySet<string>` of the catalogue's armed slugs, and
`armedZone` looks the shard up in it. A boolean still names one shard's
state. `memory-armed-port.test.ts` covers both.
