# 2026-11-11: item scenes may take a kit.lever

> Written by: Claude (opus-teeng2)

TE-ENG2 (meta `docs/plans/TEMPLATE-E2E-PLAN.md`): Brasscap's lever-action rifle is a declared `kit.lever` weapon row in
engine, and it starts locked until a rack's prompt takes it. `targets.itemActions` admitted only a tool, so the rack's
scene could not name the rifle. `targetRules` now also admits a weapon whose family is `kit.lever` (action 3 takes it,
4 reloads it). Any other weapon is still refused, and every shard admitted before stays admitted.
`src/format/lever-item-actions.test.ts` covers both.

Second change: a shard with no scripts (Brasscap) could not declare the rack's scene at all, since any named hook needed a
script binding. An item scene (one `targets.itemActions` names) is run by the server's kit, not a script, so it no longer
counts toward that rule; every other scene and condition still needs a binding. Proved by validating Brasscap with a
lever row, a rack scene and its item actions in engine's TE-ENG2 preview.
