# requires.sdk and the old grid pointer leave the schema

- FORMAT-PRUNE FP33 and FP44: `requires.sdk` and the manifest's
  `gridShardfile` had no live user (FE13: 34 live originals and 29
  engine pins, 2026-11-25), so both leave the schema, their FE7 rows
  and the lock.
- The catch that parked FP33 on 11-24: a copy written below the step
  that drops a field (a channel still on 0.1.0.4, or a made-up fixture
  carried to one) would keep it, and no reader could parse it. Raising
  the floor would have stranded prod's live 0.1.0.4 originals. Instead
  the chain mends every copy it writes, at any target
  (`format-migration-deleted.ts`): no `sdk`, and the pointer renamed to
  `shardfile`, the one way every format already admits. No live copy
  carries either field, so no live copy changes; the chain id does.
- The made-up CLI product drops its own `requires.sdk` (re-sealed source
  hash, pack's receipt), and writers never write it at any version.
- `corpus/usage.json` rides along: the delete gate needs a census from
  the last 24 hours until a release tag carries the delete.
