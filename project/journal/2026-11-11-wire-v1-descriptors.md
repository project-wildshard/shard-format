# Wire v1 descriptors (WIRE-STABILITY WR2), opus-wire

- Every class, event, act, command and hello/welcome field is now a
  descriptor in the 5.3 grammar in `packages/wire/src`, with explicit ids.
  `wire.lock.json` is generated (`pnpm lock`); the WS2 baseline moved to
  `wire.v0.lock.json`, still regenerated byte for byte by `--baseline`.
- `wire check` validates ids and bounds, refuses a stale lock and
  classifies against the baseline: 147 kept, `player.name` #54 added (it
  landed on engine main after cfd6681). Dropping it from the descriptors
  gives cfd6681's hash exactly; keeping it gives engine main's 3494901458.
- netCommand's schemas moved into wire; format's entry re-exports them
  and ships the one file. The repo's lint is strict enough that the
  moved file was rewritten (named valibot imports, named constants); the
  admission bounds are unchanged and tested.
- Codex review (J206) MUSTs folded in before push: classification now
  compares every v0 event, act and command field in v1's words
  (`cli/forms.ts`, with the intentional translations listed: presence bits
  become `optional`, flags and bytes become `enum`): 231 kept. Message
  bodies must match their tags one to one, so an `act` body on tag 2 now
  refuses. SHOULDs too: union arm ids must fit their bits, the class list is
  a literal tuple, `./events` and `./v0Field` (frozen-free, for engine's
  bundle) are exported, and the attack's target field is named `targetId`
  as NetCommand names it.

## WR3: the v1 record codec (opus-wire)

- 5.1 framing (`framing.ts`): uvarint tag and length records, the 64 KiB cap,
  minimal 5-byte uvarints, and the `W`, major bootstrap (a v0.1.x hello's
  first byte 1 answers `reload`; a higher major `retry`).
- 5.3 node codecs compiled once into closures (`encode.ts`, `decode.ts`):
  decode by the sender's table, project by id onto the receiver's, so an
  unknown field or arm is read and dropped and a missing one reads its
  default; enum words map by string.
- Tables travel as a closed binary form (`tables.ts`, `table-read.ts`),
  bounded in depth, counts and size, and checked like local descriptors.
  Cold hello and welcome (`cold.ts`, `handshake.ts`) use protobuf keys;
  a travel welcome carries only `tableHash`.
- `cmds`, `act` (`game.ts`) and `events` (`event-stream.ts`, nested records
  so one unknown event is skipped) are tagged records. The 5.1 byte
  examples are frozen in `fixtures/v1-examples.json`.
- Nothing in engine uses it yet: that is WR5. Hello is about 310 bytes with
  both client tables; the welcome's class tables arrive with WR4.
- WR3 review (J206; Codex, as the Claude quota sits at 100%): seven MUSTs
  folded in. A peer table's arrays hold 1 to 255 values of at least one bit,
  so a body bounds its count; fixed divisors are integers of 1 or more;
  quant bounds and steps are finite; any kind mismatch, nested ones too, is
  read, skipped and read as the receiver's default; text keeps a leading
  BOM; cold text keeps the 255-byte cap; an empty message and tag 0
  refuse. SHOULDs too: a bad enum default index refuses, a missing union
  reads its default arm, a welcome holds all three table blocks or none,
  and events reuse one writer. Its eighth MUST, reconciling
  `quantiseCommand`'s pitch with the v1 quant decoder, is for WR5, when
  engine switches to v1; frozen v0 and its equality test stay as they are.

## WR4: snapshots, projection, rides (opus-wire)

- `snapshot*.ts`: v1 frames keep v0's shape (owner block with f64 doubles,
  masks as wide as the sender's row, freshness bits in handle order) but
  read by the sender's class columns, so the receiver keeps every row raw,
  of a class it knows or not. Replaying the WS3 walking, fight and ride
  recordings through v1 decodes exactly what v0 decodes, frame by frame.
- `projection.ts` maps the sender's classes and columns onto the receiver's
  by id: a column it lacks is dropped, one the sender lacks reads its
  default, a bounds change converts the word; a sender lacking a required
  (position or predicted) field refuses before play. Rides get a law: the
  mount's 38 f32 words, named from `MountedBody.captureRide`; a receiver
  that can't read a law whole is never seated.
- Class tables travel in the welcome (`class-tables.ts`), checked like local
  classes (no doubles in a row, only column kinds); spawns read a class's
  initial columns by the sender's table, known class or not.
- Not yet: engine's predictor and interpolator read the projection when
  engine switches to v1 at WR5.
- A quick Node look before WB2: v1 frames are 0.5 to 0.9% larger than v0's
  on walking, fight and ride. The first v1 encoder was 1.3 to 2x slower; it
  now computes each row's mask once, indexes arrays in the hot loop and
  frames a record in one allocation, and sits within noise of v0 here. WB2
  measures it properly.

## WR3 Opus review (claude -p, after the account switch)

- Two MUSTs fixed forward on top of 918ec19: a peer table may hold no
  nested field of zero bits (an empty struct field let a few bits expand
  into millions of allocations), so decode work is linear in body bits;
  and a throwing event or body encode resets the shared writer, so no bits
  leak into the next message.
- SHOULDs folded in before `wire-v1.0.0`: the first message skips unknown
  records around its one hello; hello carries the whole `cmds` and `act`
  record bodies, envelopes included, so a later minor can add an envelope
  field or raise the bundle cap; shared defaults are frozen; a cold field
  id 0 or a known id with another wire type refuses; `tableHash` length-
  prefixes each block; the table limits (depth 8, counts 255, nodes 4096,
  64 KiB messages) are in the lock; body encodes reuse one writer and build
  a record in one allocation. New tests: zero-bit nests, writer reset, the
  64 KiB cap, a trailing byte, a narrow union, text bounds, and a seeded
  fuzz over every example (only WireDecodeError escapes).
- Left for later rows, noted in the plan: pitch and `ads` quantisation
  derived from the v1 codecs (WR5), receiver bounds on projection (WR6),
  an LRU cap on the server's per-table decoder cache (WR5).

## WR4 Opus review (claude -p)

- MUSTs fixed: ride laws now travel in the welcome (`ride-tables.ts`) and a
  receiver reads a ride's words only by the sender's law, so a law that
  gains a word never misaligns a mounted frame; a peer class table refuses
  class id 0 or a repeated id; the owner-skew proof now skews the player
  itself (a receiver without `led`, a sender with an extra owner field
  before `px`) and compares px..vz bit for bit across the ride recording.
- SHOULDs folded in: predicted fields must be `all` or `owner`; ride law
  ids fit 8 bits; a required field must sit in the same block on both sides
  and a missing class with required fields refuses; a retyped column reads
  as missing and `fixed` columns convert; a rider is seated only on an
  exact law; a baseline from another cell (after a travel) is missing;
  script x, y, z are required. New tests pin every v1 body to v0's bits,
  baseline loss and full-frame recovery, and travel.
- Moved to WR5 (plan updated): the predictor and interpolator reading the
  projection, a recorded correction through a skewed table in engine, and
  the door refusing a missing capability.

## WB2: the v1 codec's hot paths, and the gate harness (opus-wire)

- First WB2 numbers had v1 encode at 1.3 to 1.9 times v0 on commands and
  1.2 to 1.5 on the whole mix. The causes were per-field closure calls,
  `entries()` loops on the owner block, two allocations per record and
  `number[]` spreads in the cold records. Fixed: a struct's encoder is now
  generated as one straight-line function from the local descriptors
  (`encode-gen.ts`), arrays inline. Every name and bound enters the source
  as a JSON literal, a peer's table is never compiled this way, and under
  a CSP that refuses `Function` the closure loop stands in.
  `test/encode-gen.test.ts` proves both paths write the same bits for
  every record, refusals included. The bit writer and reader are inlined.
  A record is framed in one allocation (`takeRecord`, `nestedRecord`), and
  cold records are sized then written once. A thrown frame encode now
  resets the shared writer, as `encodeBody` already did.
- The v1 bytes are unchanged: every 5.1 example and the v0 bit-identity
  proofs still pass.
- Harness: `browser-benchmark.ts` prepares v0 or v1 traffic. The bridge
  that says WS3's captured packets the v1 way is split by record family
  (`v1-*.ts`), and `tagged-bytes.ts` counts the per-field-tag shape (5.6)
  for the record. `src/scripts/wire/wb2.mjs` replays all four recordings
  in Node and in Chromium at 4x, v0 and v1 interleaved with the order
  swapped each run, and judges each recording against the 5.7 gate.
- Codex review of the WB2 commit (J206), folded in. MUST: the one-allocation
  uvarint writers had lost `writeUvarint`'s range check; a negative,
  fractional, NaN or 2^32 value now refuses again (test in `handshake`).
  MUST: the dense recording is a capture graph; fixed in `571b790`.
  SHOULDs: v1 decode in the harness goes through `readMessage` (dispatch and
  singleton checks, as v0's goes through its own); runs default to four, in
  alternating order, and a recording whose encode ratio spreads more than
  0.10 across runs is reported unqualified rather than judged, with a
  failing exit on any failed gate. The tag-shape count drops scalar padding
  and counts every sent row against its baseline, gone rows and freshness.
  The NIT too: a hole in a column or slot list throws again.
- Under load 50 to 90 the four-run WB2 was mostly unqualified. Ride frames
  stayed about 10% over v0 in Chromium, so masks are now built by doubling
  and read by halving instead of a power per field, a float32's bits go
  through an aliased array as v0's do, and the plan sorts in place. The
  harness now measures eight back-to-back v0/v1 pairs and judges the median
  pair, qualified when the interquartile range is within 0.10.

- `packages/wire/bench/results/wb2-2026-11-11.json`, at a51f56f: eight

## WR6: the release rules (opus-wire)

- `wire check` now also holds the lock to the last `wire-vM.m.0` tag
  (`cli/release.ts`, `cli/release-ref.ts`), or to `--against <ref>` until
  `wire-v1.0.0` exists. A released id keeps its name, form and bounds (the
  WR4 review's bound rule, nested fields included); a removal waits out its
  deprecation window and its id stays reserved; a required field is never
  removed; a duplicate or reserved id fails; additions need a minor above the
  release's; a limit change needs a major; a patch tag leaves the lock
  byte-identical. Ids added since the release are free. A copy installed
  outside the shardfile checkout (engine's node_modules) skips the rules.
  `test/release.test.ts` holds a fixture per rule.
