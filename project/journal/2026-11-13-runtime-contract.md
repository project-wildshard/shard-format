# One runtime contract page (SHARD-AUTHORING SA19)

- `docs/RUNTIME-CONTRACT.md`: what a shard may declare (72 sections, all
  `wildshard:<name>@1`; 63 `client/plan` kinds with their side; 18
  `world.assembly` stages; 46 native-assembly hosts; the `held-melee`
  runtime plan; the named-file families; scripts; budgets; limits) and
  which engine host runs each, plus what validation refuses. Linked from
  SHARDFILE.md, SCRIPT-ABI.md and PLATFORM-FILE-FAMILIES.md, so GUIDE.md
  (SA13) can link one page.
- Generated vs hand: every list shard-format holds is generated by
  `node src/tools/runtime-contract.ts write` (lists read in
  `contract-lists.ts`, native hosts by walking the valibot variant) and
  `runtime-contract.test.ts` fails when the page drifts. Engine-only
  columns (section hosts from engine `scripts/host-ruler/roots.mjs`
  `SECTION_HOSTS`, kind page hosts and their sections from `clientPlan.ts`
  `CLIENT_FEATURES`, engine `8f613824`) live in
  `src/tools/runtime-hosts.json`; the test fails when it misses or adds a
  section or kind, but a renamed engine host goes unseen. Follow-up: an
  engine host-ruler check that reads this file from the pinned
  shard-format and fails on any difference.
- The script call limits (fuel, commands per tick) are engine's and stay
  hand-written prose, quoted from SCRIPT-ABI.md's limits table.
- Proof: a `claude -p` agent (Read/Grep/Glob only, this checkout only, no
  engine) asked "what may a shard declare at runtime, and which engine
  host serves each". Its 72 sections, 63 kind=side/server/page triples
  and 46 native hosts matched the generated lists exactly (checked by
  script). Its answer, shortened:
  - SECTIONS 72, all `@1`, at most 256, no custom sections; 41 root
    slices, 31 plain values; 7 with no engine host (metadata).
  - CLIENT_PLAN_KINDS 63 (32 both, 31 view), e.g.
    `world.movers=both/movers/installClientMoverOwners`,
    `look.painterly=view/—/setPainterlyLook`; 18 assembly stages.
  - NATIVE_ASSEMBLY_HOSTS 46 (`ammunition` … `weather.program`), server
    files only in `admission.server`; RUNTIME_PLAN_KINDS `held-melee`.
  - SCRIPTS in `sim/scripts`, `actors/return-scripts`,
    `actors/spawn-scripts`, `view/modules`, ABI v2 lanes; fuel 400,000
    per call and 2,000,000 per tick; 32 commands per call, 128 per tick;
    v1 memory 1 to 4 pages of 64 KiB, `memory.grow` refused.
  - BUDGETS `budgets` (library, sim, overlap, client), `serverBudget`
    (tickMicros ≤16,666, memory ≤25 MB, entities ≤10,000,
    commandsPerTick ≤1,024), `authorCaps` (1 to 32 players, speed 0 to
    15 m/s); memory checks report only.
  - REFUSED: unknown section or schema, unknown or unsided kind,
    unknown native host, unregistered named JSON or `custom/`, runtime
    TypeScript, module URLs or callbacks, Wasm outside the instruction
    set, over a limit or budget, `sdk: "0.3"` without `cook.json`.
  - It noted it couldn't check the engine host names from this repo,
    which the page says too.
- Review (`claude -p`): escaped `|` in table cells (eight file-family
  patterns split their rows), shipped `runtime-hosts.json` in the package
  (`files` and `exports`) so engine's follow-up check can read it, and
  tested the host entries' shape, the kinds' section names and the
  non-empty lists. Split the scripts table so `actors/spawn-scripts`
  reads server, as its host does.
