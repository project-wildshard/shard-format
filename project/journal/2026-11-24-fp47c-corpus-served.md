# The corpus counts as the chain serves it

> Written by: Claude (opus-pr6). Meta FORMAT-PRUNE FP47c; for the cut after 0.75.0, on the fp47b stack.

`corpus.repeated-manifest-fields` read the corpus as stored, so Brasscap's SS3 fixture (format 0.1, legacy by design)
kept nine words a migration already mends. The one-way inventory now migrates each corpus product to the reader's
format (`migratedCorpus`, the copy the API and cook serve) and counts that; a product the chain can't admit from the
working tree (the export's blobs aren't all committed) counts as stored. Corpus identities still hash the stored files.

The ninth word was `minimap` with an image: the door (`liftLevelStart`) drops a manifest's map image since OF9b3, but
FP34's chain step did not, so it does now, and format 0.1.0.6 refuses `manifest.minimap.image` beside the moved words
(deprecation row, break entry). The count reads 0 and its ceiling is 0.
